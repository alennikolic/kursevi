# Kreiranje Hyper-V failover klastera

Uputstvo za podizanje dvočvornog Hyper-V failover klastera na Windows Server 2025, sa deljenim storage-om preko Fibre Channel-a.

Nastavak na:
- `01. Hyperv set mreza.md` — mrežna konfiguracija hostova
- `02. Mpio unity windows.md` — MPIO i prezentacija LUN-ova
- `03. Instalacija domain controllera.md` — domenski kontroleri

---

## Preduslovi

Pre početka moraju biti ispunjeni:

- Oba hosta u domenu, secure channel ispravan
- Domenski kontroleri rade i replikacija je čista
- Vreme sinhronizovano na svim čvorovima (Kerberos toleriše najviše 5 minuta razlike)
- SET timovi i vNIC-ovi podešeni, VLAN-ovi prolaze kroz trunk
- LUN-ovi prezentovani sa storage-a i vidljivi na oba hosta
- MPIO konfigurisan, svaki LUN ima više putanja

Primeri adresa u uputstvu:

```
Domen:          example.local (NetBIOS: EXAMPLE)
Hostovi:        HOST01, HOST02
Management:     10.0.0.0/24   - HOST01 .7, HOST02 .8
Live Migration: 10.0.1.0/24   - HOST01 .7, HOST02 .8 (bez gateway-a)
Klaster (CNO):  10.0.0.5
Naziv klastera: CL01
```

### Provera preduslova

```powershell
Test-ComputerSecureChannel -Verbose
Get-ComputerInfo | ft CsDomain,CsDomainRole
w32tm /query /source
Get-NetConnectionProfile
```

Mrežni profil mora biti `DomainAuthenticated`. Ako stoji `Public`, firewall blokira RPC i validacija će pasti — detalji u uputstvu br. 3.

## 1. Instalacija rola

Na oba hosta:

```powershell
Install-WindowsFeature Failover-Clustering, Multipath-IO -IncludeManagementTools
Get-WindowsFeature Failover-Clustering, Multipath-IO | ft Name,InstallState
```

MPIO traži restart ako se instalira prvi put. Hostove restartovati jedan po jedan i sačekati da se domenski kontroler na tom hostu podigne pre nego što se dira drugi.

## 2. Priprema diskova

### Pregled

Minimalno dva LUN-a:

| LUN | Veličina | Namena |
|---|---|---|
| Witness | 1 GB | Disk witness za quorum |
| CSV | po potrebi | Cluster Shared Volume za VM-ove |

```powershell
Get-Disk | Where-Object BusType -eq "Fibre Channel" |
  ft Number,FriendlyName,PartitionStyle,OperationalStatus,@{N="SizeGB";E={[math]::Round($_.Size/1GB,1)}}

mpclaim -s -d
```

Svaki LUN mora imati više od jedne putanje, sa jednom `Active/Optimized`. Ako ima samo jednu, MPIO nije preuzeo disk ili je kablirana samo jedna veza.

### Inicijalizacija

Radi se **samo na jednom hostu**. Drugi host ostavlja diskove Offline — klaster ih sam preuzima.

```powershell
# Witness
Set-Disk -Number 1 -IsOffline $false
Set-Disk -Number 1 -IsReadOnly $false
Initialize-Disk -Number 1 -PartitionStyle GPT
New-Partition -DiskNumber 1 -UseMaximumSize |
  Format-Volume -FileSystem NTFS -NewFileSystemLabel "Witness" -Confirm:$false

# CSV
Set-Disk -Number 2 -IsOffline $false
Set-Disk -Number 2 -IsReadOnly $false
Initialize-Disk -Number 2 -PartitionStyle GPT
New-Partition -DiskNumber 2 -UseMaximumSize |
  Format-Volume -FileSystem NTFS -NewFileSystemLabel "CSV01" `
    -AllocationUnitSize 65536 -Confirm:$false
```

Napomene:

- **Bez slova diska.** Klaster montira volumene pod `C:\ClusterStorage`.
- **NTFS, ne ReFS.** Na klasičnom SAN storage-u ReFS na CSV-u radi u redirected I/O režimu, što znači da sav upis ide preko mreže do vlasnika volumena.
- **64K allocation unit** za CSV sa virtuelnim diskovima. Witness može ostati na podrazumevanih 4K.

Provera:

```powershell
Get-Disk | Where-Object BusType -eq "Fibre Channel" | Get-Partition | Get-Volume |
  ft FileSystemLabel,FileSystem,AllocationUnitSize,HealthStatus
```

## 3. Live Migration

### Podešavanje na hostovima

Hyper-V Manager → desni klik na host → **Hyper-V Settings → Live Migrations**:

- Enable incoming and outgoing live migrations
- Simultaneous live migrations: 2
- Use these IP addresses for live migration: dodati podmrežu namenjenu migraciji

**Live Migrations → Advanced Features**:

- Authentication protocol: **Kerberos**
- Performance option: **SMB**

Isto komandama:

```powershell
Enable-VMMigration
Set-VMHost -VirtualMachineMigrationAuthenticationType Kerberos
Set-VMHost -VirtualMachineMigrationPerformanceOption SMB
Set-VMHost -MaximumVirtualMachineMigrations 2 -MaximumStorageMigrations 2
Add-VMMigrationNetwork 10.0.1.0/24

Get-VMHost | ft VirtualMachineMigrationEnabled,VirtualMachineMigrationAuthenticationType
```

### Constrained delegation

Kerberos autentikacija traži delegaciju u Active Directory-ju. Bez nje migracija pokrenuta sa udaljene konzole ne uspeva.

`dsa.msc` → View → **Advanced Features** → Computers → desni klik na računarski objekat → **Delegation**:

- Trust this computer for delegation to specified services only
- Use Kerberos only
- Add → drugi host → izabrati **cifs** i **Microsoft Virtual System Migration Service**

Ponoviti u oba smera: HOST01 ka HOST02 i HOST02 ka HOST01.

Komandama:

```powershell
Set-ADComputer HOST01 -Add @{"msDS-AllowedToDelegateTo"=@(
  "Microsoft Virtual System Migration Service/HOST02.example.local",
  "Microsoft Virtual System Migration Service/HOST02",
  "cifs/HOST02.example.local",
  "cifs/HOST02")}

Set-ADComputer HOST02 -Add @{"msDS-AllowedToDelegateTo"=@(
  "Microsoft Virtual System Migration Service/HOST01.example.local",
  "Microsoft Virtual System Migration Service/HOST01",
  "cifs/HOST01.example.local",
  "cifs/HOST01")}
```

Posle promene protokola potrebno je odjaviti se i ponovo prijaviti na hostove.

## 4. Validacija

```powershell
Test-Cluster -Node HOST01,HOST02
```

Ili kroz GUI: `cluadmin.msc` → **Validate Configuration** → Run all tests.

Traje 10–20 minuta. Izveštaj se čuva u `C:\Windows\Cluster\Reports\`.

Rezultat `ClusterConditionallyApproved` znači da ima upozorenja ali nema grešaka — klaster se može kreirati. Microsoft podržava rešenje samo ako su svi testovi pušteni i nijedan nije pao.

### Česte greške u validaciji

**Duplirana APIPA adresa (`169.254.x.x`)**

Serveri sa iDRAC-om, iLO-om ili sličnim upravljačkim kontrolerima imaju USB mrežni interfejs za pass-through ka operativnom sistemu. Na više servera isti po adresi, pa ih klaster spoji u jednu mrežu i prijavi duplikat.

```powershell
Get-NetAdapter | ft Name,InterfaceDescription,Status,MacAddress
Get-NetAdapter | Where-Object InterfaceDescription -like "*Remote NDIS*" |
  Disable-NetAdapter -Confirm:$false
```

Trajnije se isključuje u samom upravljačkom kontroleru (kod iDRAC-a: Connectivity → OS to iDRAC Pass-through → Disabled). Pristup kontroleru preko njegovog namenskog mrežnog porta ostaje netaknut.

**Različiti nivoi zakrpa**

Upozorenje, ne greška. Preporuka je da svi čvorovi budu na istom nivou. Ako neki čvor ima zakrpe koje čekaju restart, restartovati ga pre kreiranja klastera — kasnije to zahteva migraciju produkcionih mašina.

**Mreže sa DHCP-om**

Privremene ili pomoćne mreže klaster uključuje u svoju konfiguraciju. Ili ih ukloniti pre kreiranja, ili posle isključiti iz klasterske komunikacije:

```powershell
(Get-ClusterNetwork "Cluster Network 3").Role = 0
```

## 5. Kreiranje klastera

Potrebna je slobodna IP adresa u management podmreži za Cluster Name Object.

```powershell
Test-NetConnection 10.0.0.5 -InformationLevel Quiet   # očekuje se False

New-Cluster -Name CL01 -Node HOST01,HOST02 -StaticAddress 10.0.0.5 -NoStorage
```

`-NoStorage` ostavlja diskove po strani da bi se dodali kontrolisano. Bez te zastavice klaster sam dodaje sve dostupne diskove i sam bira witness.

Kreiranje pravi računarski objekat (CNO) u Active Directory-ju. Nalog koji pokreće komandu mora imati pravo kreiranja objekata u odgovarajućem OU-u.

### Dodavanje diskova

```powershell
Get-ClusterAvailableDisk | Add-ClusterDisk
Get-ClusterResource | Where-Object ResourceType -eq "Physical Disk" |
  ft Name,State,OwnerGroup
```

### Quorum

```powershell
Set-ClusterQuorum -DiskWitness "Cluster Disk 1"
Get-ClusterQuorum
```

U dvočvornom klasteru witness nije opcionalan. Bez njega gubitak jednog čvora obara ceo klaster, jer preostali čvor nema većinu.

Ako je klaster kreiran bez `-NoStorage`, witness je već izabran automatski — klaster uzima najmanji pogodan disk veći od 512 MB.

Alternative kad nema slobodnog LUN-a: file share witness na nezavisnom serveru ili cloud witness.

### Cluster Shared Volume

```powershell
Add-ClusterSharedVolume -Name "Cluster Disk 2"
Get-ClusterSharedVolume | ft Name,State,OwnerNode
```

Volumen se pojavljuje kao `C:\ClusterStorage\Volume1` na svim čvorovima istovremeno.

## 6. Mreže klastera

```powershell
Get-ClusterNetwork | ft Name,Role,State,Address
```

Uloge:

| Role | Značenje |
|---|---|
| `ClusterAndClient` (3) | Klasterska komunikacija i klijentski saobraćaj |
| `Cluster` (1) | Samo klasterska komunikacija — heartbeat, CSV, Live Migration |
| `None` (0) | Isključena iz klastera |

Preimenovanje radi preglednosti:

```powershell
(Get-ClusterNetwork "Cluster Network 1").Name = "Mgmt"
(Get-ClusterNetwork "Cluster Network 2").Name = "LiveMigration-CSV"
```

Management mreža ostaje `ClusterAndClient`, namenska mreža za migraciju i CSV ostaje `Cluster`.

### Prioritet mreže za Live Migration

Failover Cluster Manager → desni klik na **Networks** → **Live Migration Settings** → ostaviti štikliranu samo namensku mrežu i pomeriti je na vrh.

Bez ovoga klaster može da migrira preko management mreže i da je zaguši.

## 7. Smeštaj virtuelnih mašina

Klasterovana virtuelna mašina mora biti **u celini** na CSV-u: virtuelni diskovi, konfiguracija, checkpointi i smart paging fajl. Ako bilo šta ostane na lokalnom disku čvora, mašina ne može da pređe na drugi čvor.

### Podrazumevane putanje

```powershell
New-Item -Path "C:\ClusterStorage\Volume1\VMs" -ItemType Directory -Force

# na svakom čvoru
Set-VMHost -VirtualMachinePath "C:\ClusterStorage\Volume1\VMs" `
           -VirtualHardDiskPath "C:\ClusterStorage\Volume1\VMs"
```

Putanja mora biti **podfolder**, ne koren CSV volumena. Koren je reparse point i Hyper-V ga odbija sa greškom `0x80070057`.

Ako komanda prođe na jednom čvoru a padne na drugom, čvor koji je ne prihvata nije vlasnik volumena. Rešenje je podfolder, kao gore, ili privremeno prebacivanje vlasništva:

```powershell
Move-ClusterSharedVolume -Name "Cluster Disk 2" -Node HOST02
```

### Kreiranje mašine

Hyper-V wizard pravi podfolder sa imenom mašine samo ako se eksplicitno zada lokacija. Ako se ostavi podrazumevana putanja, konfiguracija ide u `Virtual Machines`, a virtuelni disk direktno u koren — sve mašine se izmešaju u istom folderu.

U wizardu zato uvek štiklirati *Store the virtual machine in a different location*.

Komandom (`-Path` sam pravi podfolder po imenu):

```powershell
New-VM -Name VM01 -Generation 2 -MemoryStartupBytes 4GB `
  -Path "C:\ClusterStorage\Volume1\VMs" `
  -NewVHDPath "C:\ClusterStorage\Volume1\VMs\VM01\Virtual Hard Disks\VM01.vhdx" `
  -NewVHDSizeBytes 100GB `
  -SwitchName "vSwitch-VM"

Set-VMNetworkAdapterVlan -VMName VM01 -Access -VlanId 20
Add-VMToCluster -VMName VM01
```

Najsigurniji put kroz GUI je **Failover Cluster Manager → Roles → Virtual Machines → New Virtual Machine** — wizard sam nudi CSV lokaciju i odmah dodaje mašinu u klaster.

### Provera da ništa nije ostalo lokalno

```powershell
Get-VM VM01 | ft Name,Path,ConfigurationLocation,SnapshotFileLocation,SmartPagingFilePath
Get-VMHardDiskDrive -VMName VM01 | ft Path
```

Sve putanje moraju počinjati sa `C:\ClusterStorage\`.

### Premeštanje postojeće mašine

```powershell
Move-VMStorage -VMName "VM01" -DestinationStoragePath "C:\ClusterStorage\Volume1\VMs\VM01"
```

Radi i dok mašina radi, ali na praznoj mašini je brže ugasiti je.

## 8. Provera rada

### Stanje klastera

```powershell
Get-Cluster | ft Name,Domain
Get-ClusterNode | ft Name,State,DynamicWeight
Get-ClusterQuorum
Get-ClusterSharedVolume | ft Name,State,OwnerNode
Get-ClusterNetwork | ft Name,Role,State
Get-ClusterGroup | ft Name,OwnerNode,State
```

### Test live migracije

```powershell
Move-ClusterVirtualMachineRole -Name VM01 -Node HOST02 -MigrationType Live
Get-ClusterGroup VM01 | ft Name,OwnerNode,State
```

Tokom migracije pustiti neprekidan ping ka mašini sa treće stanice. Gubitak jednog paketa je prihvatljiv, duži prekid znači da migracija ide preko pogrešne mreže ili da je autentikacija pala nazad na drugi mehanizam.

### Test ispražnjavanja čvora

```powershell
Suspend-ClusterNode -Name HOST01 -Drain
Get-ClusterNode | ft Name,State
Get-ClusterGroup | ft Name,OwnerNode,State
```

Sve uloge moraju preći na drugi čvor bez prekida. Vraćanje:

```powershell
Resume-ClusterNode -Name HOST01 -Failback Immediate
```

### Test neplaniranog otkaza

Na test mašini, van radnog vremena: naglo isključiti jedan čvor i proveriti da se uloge same podignu na preostalom. Ovo je jedini test koji zaista potvrđuje da quorum radi.

## 9. Cluster-Aware Updating

Omogućava primenu zakrpa bez prekida rada — čvorovi se pate jedan po jedan, uz automatsko ispražnjavanje i vraćanje uloga.

```powershell
Add-CauClusterRole -ClusterName CL01 `
  -DaysOfWeek Sunday -WeeksInterval 4 `
  -MaxFailedNodes 0 -RequireAllNodesOnline -Force

Get-CauClusterRole -ClusterName CL01
```

Provera bez primene:

```powershell
Invoke-CauScan -ClusterName CL01 -CauPluginName Microsoft.WindowsUpdatePlugin -Verbose
```

## Gašenje i paljenje klastera

Za planirano gašenje, selidbu ili radove na napajanju.

**Gašenje:**

1. Ugasiti ili migrirati virtuelne mašine
2. Zaustaviti klaster: `Stop-Cluster`
3. Ugasiti domenske kontrolere (ako su virtuelni, na lokalnim diskovima čvorova)
4. Ugasiti hostove
5. Ugasiti storage uredno, kroz njegov upravljački interfejs

**Paljenje:**

1. Storage prvi, sačekati da svi kontroleri budu Online
2. Hostovi
3. Provera vidljivosti LUN-ova: `Get-Disk`, `mpclaim -s -d`
4. Domenski kontroleri
5. Klaster: `Start-Cluster`
6. Virtuelne mašine

Ako se oprema fizički seli, zabeležiti kako je kablirana pre rasklapanja. Promena portova menja broj i raspored putanja, pa MPIO konfiguraciju treba proveriti ponovo.

## Česti problemi

| Simptom | Uzrok | Rešenje |
|---|---|---|
| Validacija: duplirana `169.254.x.x` | USB NIC upravljačkog kontrolera (iDRAC, iLO) | Isključiti adapter ili pass-through u kontroleru |
| Validacija: `RPC server is unavailable` | Mrežni profil `Public` | Restart NLA servisa ili adaptera |
| `Set-VMHost` javlja `0x80070057` na CSV putanji | Koren CSV-a je reparse point | Koristiti podfolder |
| `Set-VMHost` prolazi na jednom čvoru, pada na drugom | Drugi čvor nije vlasnik CSV volumena | Podfolder ili prebaciti vlasništvo |
| Live migracija pada sa greškom autentikacije | Nema constrained delegation | Podesiti delegaciju u oba smera |
| Migracija spora ili zagušuje management | Pogrešna mreža za migraciju | Live Migration Settings — izabrati namensku mrežu |
| VM ne može da pređe na drugi čvor | Deo fajlova na lokalnom disku | `Move-VMStorage` na CSV |
| Gubitak jednog čvora obara klaster | Nema witness-a | `Set-ClusterQuorum -DiskWitness` |
